# 图片 → 逐笔绘画过程（image2strokes）

把一张图片丢进去，自动提炼出它被**一笔一笔画出来**的完整过程并回放：

- **每一笔都是纯色**——笔内不显示照片纹理/渐变，就是实打实的一块颜色；
- **允许互相覆盖**——先画的颜色会被后画的盖住，像真的画画一样；
- **成品尽量贴着原图**——插画/海报类目视几乎一致，照片类会被"风格化"成平涂画（见下面的实测数据）；
- **纯前端**：算法全部跑在浏览器里，不上传任何图片，没有任何后端依赖。

在线体验：<https://longguanhong0755.github.io/image2strokes/>（GitHub Pages）

## 怎么用

1. 打开页面（或本地起个静态服务器：`python -m http.server 8000`，然后访问 `http://127.0.0.1:8000/`）；
2. 拖入/选择一张图片，或点三个示例按钮；
3. 等 8~20 秒（提炼过程会显示进度），页面开始**逐笔回放**绘制过程；
4. 期间可以：调速（0.25×~4×）、拖动进度、显示/隐藏笔尖与运笔参考线、勾选"对比原图"直接看原图；
5. 画完会给出**差异读数**（整体差异 + 逐像素细节差异）。

参数：颜色数（16~40，照片建议 32~40，插画 24 够用）。

## 实测（三张示例图，颜色数 = 24）

| 示例 | 类型 | 笔数 | 回放时长(1×) | 平均差异 | 可见差异像素 |
|---|---|---|---|---|---|
| sample-1 | 扁平插画（本仓库自绘，CC0） | 6181 | 248s | 2.23/255 | 3.23% |
| sample-2 | 猫咪照片（Wikimedia CC0） | 17878 | 313s | 10.24/255 | 43.04% |
| sample-3 | 1927 年美国航空邮件海报（公有领域） | 17739 | 313s | 9.01/255 | 22.77% |

> "可见差异像素"= 单通道差值 > 8 的像素占比（与页面上读数同口径）。
> 插画的差异几乎全在色块交界的 1px 过渡带；照片/扫描件本身是连续色调 + 颗粒，
> 用纯色平涂去还原时逐像素差异必然大，但目视是"同一张画面的平涂版"。
> 页面里换 32~40 色再跑照片，差异会明显下降。

## 它是怎么画的

1. **分块**：先做轻度去噪（median3，纹理重的图再加两次 box 模糊），转到 Lab 空间做 k-means（默认 24 色，相近色再合并），
   全图归类后取连通域得到"色块"，小碎块并入颜色最近、接触最多的邻块。
2. **勾线**：所有"细"的区块（不论深浅）合并成线稿层，Zhang-Suen 细化取骨架、两次 BFS 求最长路径 →
   沿骨架走一条笔；复杂线稿用**分支队列**反复"画最长、剩余再拆"，保证不断线。
   笔尖按颜色深浅自动选：深色硬笔尖（钢笔），浅色软笔尖（细笔刷）。
3. **铺色**：每个色块沿主轴方向一档一档来回涂，笔宽按块厚自适应，档间 35%+ 重叠；
   每一笔按弧长切段、**逐段取局部纯色**（颜色接近的相邻段合并成一笔），所以渐变区域也能一档档过渡出来。
4. **补笔修形**：把"当前画布 vs 原图"差异大的地方找出来（按 72px 分块、按颜色二分、按连通切开），
   用贴着错误带宽度的细笔补上，一轮轮把阈值收紧；**大面积平滑渐变差异不补**（那属于平涂风格本身，补了会花）。
5. **回放**：每笔都是一条走廊多边形 + 笔尖轨迹 + 一个纯色；回放时按"已扫过 + 笔尖前沿"逐帧合成，
   笔尖前方带半透明湿边，画完落成实色。进度条拖动靠关键帧位图，秒级响应。

## 细节上的几个坑（都在代码里处理了）

- 平涂和"透出原图"是两种完全不同的取舍：平涂必须在**边界**上想办法，所以取色时要避开区块边界的混色像素（否则会画出一圈亮边）；
- 细而弯的区块用"平行直线笔刷"必然漏涂，必须走骨架笔；
- 补笔只在**结构性错误**（线稿、边界过渡带）上做，大片渐变差异补了会变成块状拼贴；
- 照片纹理会让区块数爆炸（几千块 / 上万笔），所以有总笔数上限与收益收口。

## 目录

```
index.html            页面（上传 + 参数 + 画布 + 回放控件）
js/app.js             主线程：图片预处理、界面、回放引擎、差异读数
js/worker.js          Worker 入口
js/pipeline.js        全部算法（纯 JS，无依赖；也能在 Node 里跑）
samples/              示例图（含授权说明见 samples/CREDITS.md）
dev/                  开发用小工具
  run_test.mjs        Node 里直接跑管线并出还原度数据（量化回归用）
  mkraw.py            把图片转成 Node 测试用的 .raw
  make_sample_illustration.py  生成 sample-1（自绘 CC0 插画）
  probe_point.mjs / diag_strokes.mjs  排查"某个像素/某条线为什么不对"
```

本地跑回归：

```bash
python dev/mkraw.py samples/sample-1.jpg dev/s1.raw
node dev/run_test.mjs dev/s1.raw 24 out.rgb
```

## 兼容性

需要支持 `Worker` / `Canvas 2D` / `createImageData` 的现代浏览器（Chrome / Edge / Safari / Firefox 近几年版本都可以）。
1024px 的图在普通笔记本上提炼约 8~20 秒，回放本身很轻（每帧只合成当前一笔）。
