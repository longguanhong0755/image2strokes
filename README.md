# 图片 → 逐笔绘画过程（image2strokes）

把一张图片丢进去，自动提炼出它被**一笔一笔画出来**的完整过程并回放：

- **每一笔都是纯色**——笔内不显示照片纹理/渐变，就是实打实的一块颜色；
- **允许互相覆盖**——先画的颜色会被后画的盖住，像真的画画一样；
- **过程像人画的**——分四步推进：铺底色（整片刷满、不预留空位）→ 分层铺色（一个对象画完再画下一个，
  后画的压住先画的，遮挡就是这么来的）→ 收形 → 点睛/题字落款；
  笔形带手抖、弧线与宽窄变化，换地方时笔尖会抬起来走过去（纸面上留一条浅弧线）；
- **自动按图判断**——纹理强的图（照片/扫描件）自动换一套参数（色数提到 40~44、笔更细、放宽笔数上限）；
- **笔数省**——同一格、同一色阶的散点补笔会**合并成一笔**（掩膜互不相交，像素结果完全等价），
  照片类笔数比逐点补少一半左右，回放更清爽；
- **可选风格与时长**——平涂马克笔 / 铅笔速写 / 油画厚涂；过程 2 / 4 / 8 分钟；
- **能导出**——整段过程录成 WebM 视频、笔触脚本 JSON（含裁剪掩膜）、成品 PNG；
- **成品尽量贴着原图**——插画可见差异约 1%、海报约 10%、照片约 19%（见下面的实测数据）；
  最后一层细笔会把纹理颗粒、毛发也点回来，所以近看也不糊；
- **纯前端**：算法全部跑在浏览器里，不上传任何图片，没有任何后端依赖。

在线体验：<https://longguanhong0755.github.io/image2strokes/>（GitHub Pages）

## 怎么用

1. 打开页面（或本地起个静态服务器：`python -m http.server 8000`，然后访问 `http://127.0.0.1:8000/`）；
2. 拖入/选择一张图片，或点三个示例按钮；
3. 等 20~40 秒（提炼过程会显示进度），页面开始**逐笔回放**绘制过程；
4. 期间可以：调速（0.25×~4×）、拖动进度、显示/隐藏笔尖与运笔参考线、勾选"对比原图"直接看原图；
   画布下方有一条四步进度条（铺底色 / 铺色 / 题字 / 点睛），实时标出当前画到哪一步；
5. 画完会给出**差异读数**（整体差异 + 逐像素细节差异）；
6. 三个导出按钮：**导出视频**（把整段过程快放录成 WebM，约 24 秒）、
   **导出笔触**（JSON：笔形 + 轨迹 + 纯色 + 裁剪掩膜 PNG）、**存成品图**（PNG）。

参数：
- **颜色数**：默认"自动"（统一 40；纹理特别强的照片会走 44），也可以手动锁 16 / 24 / 32 / 40；
- **笔触风格**：平涂马克笔（默认，保真最高）/ 铅笔速写（笔更细、起收笔更明显）/ 油画厚涂（笔更宽、重叠更多）；
- **过程时长**：快看 2 分钟 / 标准 4 分钟 / 慢工出细活 8 分钟（这一档还会把补笔修得更细）。

## 实测（默认设置：颜色数自动、平涂马克笔、4 分钟）

口径（都是**离线同一脚本**、拿 raw 尺寸的管线画布跟原图逐像素比，改版前后各跑一次对照）：
`笔数` = 管线输出的笔数（已收尾删笔）；`平均` = 逐像素各通道差的均值；`可见` = 最大通道差 > 24 的像素占比；
`底色帧空洞` = 只画完底色层时，画布上"原图有色却没画上"的像素数（回放里最先看到的那一步）。
> 注：浏览器里画布是**带抗锯齿**渲染的，同一个成品的读数会比这里的"管线画布口径"略高；
> 本表的"上一版"列也一并按同一脚本重测过，两列可比。

> **"提炼提速 + 图层形状改圆盘核"这一轮**（2026-10-19，起因是问"还有什么可优化的"）：
> ① **提炼快了 1.4~1.5 倍，成品逐像素不变**。新旧两版在同一台机器上**交替跑、各取最小值**（避开机器抖动）：
> 插画 58.0 → **38.6 秒**、海报 57.0 → **40.9 秒**；三张图的成品 md5 完全一致。四处改动，全是"同一件事别算两遍"：
> 全图"最近调色板色"原来跑了两遍（一遍算每个调色板色的代表 RGB、一遍算每像素的归属），合并成一遍；
> `srgb2lab` 每次调用都新建一个数组和一个闭包（百万像素 = 百万次分配），改成写进调用方的缓冲；
> 背景色场那 4 遍全幅 3×3 模糊去掉全部边界判断、改双缓冲（输入是 float32，9 个数相加在 float64 里
> 本来就是精确的 ⇒ 展开与重排都不改任何一位）；残差每轮把"整幅最大通道差"算三遍（补笔掩膜 / 瓦片扫描 /
> 可见差异计数），把前两遍合并成一遍（它们看的是同一份画布）。
> ② **中途帧里字和飞机边上的方块"耳朵"没了**。图层"完整形状"（补出"被上层盖住的部分"）原来用**方形核**
> 闭运算，斜边和拐角处会推出方角小凸起。改成**圆盘核**（走距离变换，八边形近似），外扩系数 0.8 → **0.55**
> （只要盖到上层的一半就够，再往外是上层自己的地盘）——插画和海报的成品 md5 与上一版**完全一致**，
> 只有回放中途的样子变干净了；照片的读数还略好（平均差 4.41 → 4.39、可见差异 2.06% → 2.04%）。

> **"细描边 + 底色"这一轮**（2026-10-18，起因是用户看回放点出三条：飞机还是被啃、字也出了问题、底色没涂满）：
> ① **底色帧的白洞 = 删笔判据的漏洞**。`dropDead` 原本按"在**最终画布**上零贡献"删笔，可一笔完全可能
> "落笔时画上了、后来被别的图层盖掉"——它在回放里真的画过一笔，删了就在那一层刚画完时留一个洞。
> 海报实测有 **19 支底色层的笔**是这种情况，删完底色帧上是 **7623 个白点（0.92%）**。判据改成
> **"曾被别的层盖过的一律不删"**（被本层后来的笔随手压过去的照删）⇒ 底色帧 0 洞，代价是海报多 1562 笔。
> ② **"被啃"和"字出问题"是同一个根：`edgeSnap`（边界按颜色重判）**。它的判据只看"自己区色 vs 邻居区色"，
> 于是把**真的细描边**啃掉一圈：海报红描边外缘那圈深色像素离蓝底"数字上更近"，就被判给了蓝底
> （AIR MAIL 区域 2200 个像素被翻）。关掉它：AIR MAIL 可见差异 **5.23% → 2.46%**、飞机 4.36% → 3.89%、
> 照片整幅 3.07% → 2.57%——三张图全赢，只有海报整幅靠"把背景纸纹噪点刷成蓝底"赚回的那 0.1 个点没了。
> ③ **它当初是在替"调色板太小"擦屁股**：海报是印刷扫描件，那圈深色描边在 24 色里根本没有对应的中心，
> 量化只能把它塞给橙字或蓝底 ⇒ 边上一圈被涂成浑浊的棕带（"Gets first attention" 可见差异 11.4%）。
> **自动色数 24 → 40** 之后同样的问题不再出现（该区 3.5%），而且三张图的整幅读数都更好或持平。
> ④ **层不再碎**：绘制顺序从"按面积从大到小"改成**同色合并成"一趟"**——层与层之间只有"谁盖谁"这条硬约束
> （两张完整形状相交就不能换先后），其余顺序自由，于是优先挑"跟上一笔同色、又离笔尖近"的那层，
> 同一支笔一路把同色的东西画完（一整排橙字连着写完）。海报 470 个层现在收成几十趟。

> **"笔形端头 + 边界"这一轮**（2026-10-18，起因是用户看回放点出两条：飞机还是没做到 1:1；中途涂色出现没涂满
> ——截图是 "first" 的 S 上啃出的几个蓝色楔形缺口）：
> ① **中途那些楔形缺口 = `ribbonProf`（变宽笔形）的端头扫错了半边**。它跟早就修好的 `ribbon` 不一致：
> 端头圆头绕的是**侧后方**，于是每支笔的前半球盖不住、还在笔身上啃出一个三角缺口。细长层（字母、飞机、
> 红描边）全走这条路径，实测 1009 支笔的几何缺口 55700px，其中 12248px 后来没有任何笔画到。
> S 那一层 11 支主笔只盖住 82.4%（漏 995px，最大一块 491px 就是用户截图里那个楔形），飞机 16 支只盖 80.8%
> （漏 3099px），剩下的靠**每层自检的矩形补丁**兜底——海报大层的笔里 **43% 是补丁**，S 那一层 113 支补丁占 91%，
> 回放里就是"没涂满 + 补丁乱飞"。端头对齐 `ribbon` 之后：细长层主笔覆盖率中位 92.8% → **99.9%**，
> 补丁 1397 → **105** 支，S 与飞机的主笔覆盖 **100%**（那一层一次画满）。
> ② **"又大又厚"的判据用的是假厚度**。残差把"又大又厚"的错误块整块跳过（怕在平滑渐变上补出块状拼贴），
> 但厚度是按 `面积 ÷ 外框边长` 算的——字母/飞机那圈**深色描边是细环**，这么算能得出 46px 的假厚度，
> 整条描边被当成"大片平滑渐变"永不补。换成**距离变换的真实厚度**、门槛 8 → 30（照片类仍保持 8）：
> 海报可见差异 2.01% → 1.45%、"明显差异(>48)" 0.35% → **0.04%**、最大误差 233 → 138，笔数还少了 874 支。
> ③ **每层画完主动描一圈边界**。主笔是"整层一个色"，而边界那圈在原图里是混色/深描边（海报的深红描边、
> 照片发丝边的灰过渡），平涂上去必然差一截。以前是"端头有缺口 ⇒ 自检发现洞 ⇒ 补丁按局部色补"**歪打正着**
> 把边刷准的；端头修好之后没有洞了，这件事得明着做：每层画完，把自己那圈 1~2px 的边界用**局部色**补一遍。
> 三张图全赢：海报 2.01% → **1.27%**、照片 2.58% → **2.06%**、插画 0.39% → **0.33%**。
> ④ **出界笔只许压在"已经画过"的对象上**。铺色时允许一小部分笔压到轮廓外（像人一样），但蓝底第 30 层有
> 2 支出界笔排在飞机**之后**画，把飞机 95 个米色像素盖成蓝色（"飞机被啃"的最后一处）。加顺序约束之后
> 飞机区"原图米色→成品蓝" = **0**，深色细节对上率 49% → 73%。
> ⑤ 底色那三块浅蓝（原图 54,97,144 被涂成 24,74,127，共 8257px）也跟着修好了（对上率 99.9%）。
> ⑥ 口径坑记一笔：`dropDead` 删笔会把 `strokes` 数组重排，所有"按笔号记账"的诊断（`from/to`、`gapAt`、
> `layerEnds`）在成品上读就是错位的——诊断脚本必须跑 `dropDead:false`。

> **"图层栈"这一轮**（2026-10-18，起因是用户看回放截图点出四条硬伤：直线被画成波浪、铺色中间有空洞且最右边没铺到、
> 黑框没涂满要回头再补、底色给字预留了位置——并说"应该是很多个图层叠加，不是只有底 + 上两层"）：
> ① **分层重做**：原来是"一个层核一个区块"（蓝底被色带切成几十条各画各的、黑框四条边也各画各的）。
> 现在"**挨着 + 颜色相近**"两个条件同时满足才并成一层——一整片蓝底是一层、一整圈黑框是一层；
> ② **每层算出"完整形状"**：被上层盖住的部分也要画（按上层的厚度做形状闭合推断；判据只认"上层"，
> 所以飞机两翼之间那片天不会被补进飞机里）。**底色层的完整形状就是整幅**——一个洞都不留，
> 字和飞机的位置也照刷，画完再用各自的颜色盖回来（后画的盖住先画的）；
> ③ **每一层"一次过"**：落笔前先算"这一层所有档合起来盖到哪"，掩膜里没盖到的像素就地加宽最近的那一档
> （不新增笔画）；细长层同样（中轴拉直后笔形切掉的凸起按缺口加宽）。落笔后还会再自检一遍兜底；
> ④ **细长的一层走中轴线**（黑框、支柱、字的笔画）：骨架先拉直（RDP，直线段一笔到底）、笔宽跟着形状走、不抖——
> "直线画成波浪"就是这么治的；窄的一层手抖幅度也按宽度缩，不然边缘就花了。
> 顺带修掉一个老坑：相邻两段拼接处的**重复点会让笔形在那个顶点掐细**，光栅出来正好是一个三角缺口——
> 这就是"铺色中间那些白三角"的根（`ribbon` 求方向时要跳掉重复点）。
> 代价：照片笔数 24213 → 39786（分层更细，每一层都按自己的完整形状刷一遍）。

> **"少笔 + 一次过"这一轮**（2026-10-18，起因是用户第二轮反馈：飞机的直边"像被啃过"、铺色时中间有空洞/最右边没铺到
> （虽然随后补上了，但希望"画的时候一次就过"）、以及"看看有没有多余不用的笔画，用最少的笔画画出最好的效果"）：
> ① **补丁按颜色分裂**：一块错误里深浅混在一起时（跨渐变、压在深色描边上），原来用一个均值色补上去，
> 浅的那半被刷深——飞机边上的"深色楔子"、层自检补出来的"灰斑"都是这么来的，而且下一轮又被判成错、再补一遍。
> 现在补漏、每层自检的补丁都先按颜色二分（方差最大通道、中位数切），各用各的均值色：一次补准，不反复；
> ② **铺色"一次过"**：落笔前先按网页端口径算一遍"这一层所有档合起来盖到哪"，掩膜里没盖到的像素
> **就地加宽离它最近的那一档**（不新增笔画）——白缝在铺的时候就补平，不用等事后自检补；
> 细长层同样处理（中轴被拉直后笔形切掉的凸起，也按缺口加宽）。取色另用一套"窄笔形"，
> 免得加宽后把旁边的深色描边平均进来；
> ③ **并笔取加权均值**：一条长笔跨过渐变时原来拿第一段的颜色，末端整段刷成起点色（插画粉色圆里那块方块状鬼影）；
> 改成按段长加权平均，并笔的色差门槛也收到和分段一致（6）。这一条同时把三张图的保真度都拉高了
> （海报可见差异 10.06% → 7.70%）；
> ④ **掩膜边界重判**：目标图边上有 1~3px 混色带，量化会把它们随机分给两侧、甚至自己成一层被涂成灰条。
> 现在：边界像素按"颜色离哪边近"重判、夹在两层纯色之间的过渡带按最近的一侧并进去、
> 再走一遍 5x5 压倒多数表决抹掉锯齿（3px 宽的细杆/笔画不会被吃掉）；
> ⑤ **修掉一个一直在的老坑：`ribbon` 的圆头方向反了**——圆头画在笔的**后半侧**，笔形在两端自己折回去，
> 非零环绕在折角里正负相抵 ⇒ 绕数归零 ⇒ 那一段画出来是个破洞。短笔（笔宽 > 笔长）整个就是折角，
> 所以每次换色的接头处都留一个 20px 的白斑——这就是"铺色中间那些空洞"的真根（也是每层自检要补 4 万像素的原因）。
> 修好后：底色层"没盖到"的像素 4.4 万 → **0**，回放中段的内部白斑 300 个/1.6 万像素 → **0**；
> ⑥ **收尾删掉"零贡献笔"**：关键帧回放时顺手记下"每个像素最后是被哪一笔画上的"，一笔都没留下的直接删——
> 成品**像素级不变**（md5 一致），但回放里少了"在同一个地方又点一下"的多余动作。
> 读数（离线同一脚本，v16 → 现在）：插画 6806/1.72/1.10% → **4960/1.28/0.90%**、
> 照片 39786/5.33/19.26% → **24835/5.19/16.81%**、海报 22455/4.12/10.06% → **18268/3.89/8.20%**。
> 三张图**笔数都更少、保真度都更好**；空白点仍为 0。代价：离线渲染时间约 1.6~2 倍（多了"落笔前的联合覆盖自检"和几遍边界重判）。

> **"保真度"这一轮**（2026-10-18，起因是用户要求"相似度尽可能高、要精确到像素级"）：
> 先做了误差分解（按原图的平坦/纹理/边缘三类分别统计），发现**最大的错不在细节、在平坦区**——
> 海报的平坦像素占 78%、其中 26% 可见错，而"完美平滑"的理论下限只有 3%。四个根因逐个治：
> ① 长笔把跨过的渐变抹平（取色分段合并阈值 42→8，≈14/通道 → 3/通道）：主笔多 60%，可见差异直降 5 个百分点；
> ② 补笔合并太保守（固定色桶 ⇒ 合并比只有 1.7:1）：改成跟"这一组的均值色"比，同样的轮次少用 37% 笔数；
> ③ 补笔**根本没跑完就被预算砍掉**（海报停在 20%、照片停在 29% 时其实还在每轮降 4 个点）：
> 加了"自适应续补"，一路补到收益低于 0.25 个百分点才收手；
> ④ 纹理像素原本被排除在补笔之外（纸纹不补）：改成主笔照旧不画纸纹（铺色干净），
> 但细笔补笔把颗粒/毛发点回来——照片 25.5% → 19.6%。
> 另外补了两处"过程"上的硬伤：**底色层刷完当场自检补缝**（铺色阶段中段起画布 0 白点）、
> **补笔沿希尔伯特曲线排序**（笔尖一片一片挪，笔间移动 308 万 → 69 万 px，≥200px 跳转 5668 → 50 次）。
> 代价是笔数多了 1.5~2 倍（回放仍是 4 分钟，每笔的节奏自动压缩）。

> **"纹理抹平 + 细线跟对象"这一轮**（2026-10-18，起因是用户放大看海报："和原图极度不相符"）：
> ① 纸纹/噪点从画面里剔除（不画、不参与底色取色、残差也不补）——蓝底从"斑驳"回到干净，
> 飞机内部不再有灰块，放大对比明显更接近原图；② 细线分两拨画——贴在对象上的（猫嘴、胡须、字的描边）
> 跟着对象一起画完，只有落在底色上的题字留到最后；③ 起稿阶段默认关闭（勾出来的灰线随即被铺色盖掉，
> 对成品零贡献，回放开头却是一段"乱线"）。海报笔数 12493 → 10510（-16%）、可见差异 20.50% → 20.02%；
> 代价是海报的逐像素平均差 +0.58（纸纹不再被画出来，纹理区差异上升，属于预期）。
> 猫的关键帧：猫嘴在第 692 笔（铺色阶段）就跟着猫脸画完了（旧版是 98% 处才写）。

> 最近这一轮是**"一个区块内一笔到底"**（同一区块来回的几档接成一条连续走笔，见"坑"里那条），
> 铺色阶段的笔数几乎砍半（插画 726→329、照片 5268→3091、海报 3890→2133），
> 而且三张图的成品指标**都比不连笔更好**——连笔顺带少了重叠笔互相覆盖出来的"花"。
> 总笔数没降那么多，是因为残差补笔的轮次预算按笔数算：省下来的额度会被补笔吃掉一部分换质量
> （照片那张因此多跑了一轮：可见差异 34.4% → 30.6%，总笔数还降了 9%）。
> 「笔数」列是**线上页面里的真实读数**（示例图经 canvas 解 JPEG + 缩放，和离线 raw 会有几百到几千笔的差别）；
> 「成品口径」列是同一份像素走离线复算的**前后对照**，与网页端"看成品"的结束读数一致（误差 <0.5 个百分点）。

> **空白点**＝成品上"该有颜色却是白的"像素。三张图现在都是 **0**（网页端还会在成品上再自检一遍，
> 见"坑"里最后两条）。「成品口径」的读数是按**网页端真实渲染方式**（canvas 抗锯齿多边形 ∩ 1 位硬遮罩、
> 逐笔 source-over、非零环绕）复算出来的，和页面里显示的读数一致（页面还会另给一个"缩到 1/4 再看"
> 的整体差异，插画约 1.92/2.80%，照片约 6.4/25%，海报约 5.5/18.5%）。
> 插画类目视几乎与原图一致，差异集中在色块交界的 1px 过渡带；
> 照片/扫描件本身是连续色调 + 颗粒，用**纯色平涂**去还原时逐像素差异必然大（那是风格化）。
>
> 三种风格的对比（同一张插画）：平涂马克笔 1.92/2.80%、铅笔速写 1.95/3.02%、油画厚涂 ~2.15/3.01%；
> 时长档位：快看（2 分钟）2.32/4.29%、标准 2.14/3.05%、慢工出细活（8 分钟）2.11/2.85%。

## 它是怎么画的（四步，像人一样推进）

0. **准备**：轻度去噪（median3，纹理重的图再加两次 box 模糊）→ Lab 空间 k-means（默认 24 色，相近色再合并）→
   连通域得到"色块"，小碎块并入颜色最近、接触最多的邻块。
   **纸纹/噪点不画**：面积小、对比弱的碎块（老海报/扫描件的斑驳）判为"纹理"并进邻块——
   不参与底色取色、残差也不补，放大看才不会一片脏。
   **细线（文字笔画、轮廓线）也并进邻块**——它们的位置在铺色阶段会被底色铺满，
   自己留到该写的时候再"写"（见第 2、5 步），不是先挖个洞再一点点补。
1. **铺底色**：底色层的"完整形状"就是**整幅**（除了纸底）——它铺色时把"上面要画的东西"的位置也一并刷满
   （人铺底色就是整片刷过去，上面的字和主体等会儿盖回来，不会先绕着它们挖一圈洞）；
   取色走一张"背景色场"：看得见的地方用平滑图，看不见的地方（被字/主体盖住的）按最近的底色像素推出来，
   所以整幅任何位置都能取到底色，且不会被字身上的颜色污染。
   **刷完当场自检**：把这一拨笔光栅化一遍，把"没盖到"的边角/楔形立刻补上——
   实测底层会漏掉十几像素的空斑（多半长在两个区块交界的楔形上，两边都以为对方会刷到），
   补完之后从铺色阶段中段起，画布就是 **0 白点**，不用等最后的补漏。
2. **铺色（图层栈）**：先分"层"——**挨着 + 颜色相近**的区块并成同一个对象（一整片蓝底、一整圈黑框、
   一个字母各是一层），层按面积从大到小排（纸底 → 底 → 中景 → 主体 → 细节），**一层画完才画下一层**；
   每一层按"完整形状"刷（含被上层盖住的部分），细长的一层走中轴线（直线一笔到底），
   每层刷完当场自检补缝。
   每个区块沿主轴一档一档来回涂，**方向逐档交替并从笔尖近的一头起手**，
   再把"颜色相近的连续几档"**接成一条连续走笔**——涂到头拐个弯接着涂回来，不是一档抬一次笔
   （像人拿宽笔来回扫；档间色差超过 `joinCd` 才另起一笔，见下面的坑）；
   笔形带手抖与浅弧线（同一区块内的笔一起漂，所以不会漏缝）、宽窄起伏（中间粗两头细）；
   一部分笔（只在大色块上）**允许压出轮廓外** 2px，后面被别的颜色覆盖回来；
   每一笔按弧长切段、逐段取局部纯色（颜色接近的相邻段合并成一笔）。
   **贴在对象身上的细线跟着它一起画**：一个对象铺完色，立刻把它的细线（猫嘴、胡须、字的描边）
   写上去——猫画完时嘴就在，不拖到最后。
3. **收形**：按"哪里不像就补哪里"修边缘、压暗部（两轮中等阈值的补笔）。
   补笔的瓦片按"所属对象"排序、落盘的补丁**沿希尔伯特曲线排**——回放时笔尖是一片一片挪过去的，
   不是全画面乱跳（只改顺序，像素结果不变：各补丁掩膜互不相交）。
   实测这一步把笔间移动从 308 万 px 降到 69 万 px、≥200px 的跳转从 5668 次降到 50 次。
4. **点睛**：细笔补细节（把"当前画布 vs 原图"差异大的地方按 72px 分块、按颜色二分、
   按连通切开，用贴着错误带宽度的细笔补上，一轮轮收紧阈值）。
   排定的七轮（阈值 30→7）跑完之后**继续自适应续补**：阈值一轮降 0.6，一直到"这一轮的收益
   低于 0.25 个百分点"才收手——老版本是被固定档位+笔数预算砍掉的，海报停在 20%、照片停在 29%
   的时候其实每轮还在降 4 个点，根本没收敛。
   **大面积平滑渐变差异仍然不补**（那属于平涂风格本身，补了会花）；
   细线像素跳过、留到下一步；**纹理像素会补**——主笔照旧不画纸纹（铺色干净），
   但这一层用贴着像素的细笔把颗粒/毛发点回来（照片可见差异 25.5% → 19.6%）。
   小于 128px 的错误块直接并进"补丁笔"（1 位掩膜、口径比骨架笔更准，还能合并成更少的笔）。
5. **题字落款（最后一层）**：只写"落在底色上的"细线（题字、落款、印在底上的小字），按**行**组织——
   一行画完再画下一行，行内从左到右（像人写字，不是全画面挑最近的一块乱跳）。
   贴在对象上的细线（猫嘴、胡须、描边）已经在铺色阶段跟着对象画完了，这里不再重复。
6. **补漏与接缝**（收尾）：
   **接缝修正**——画布上"不该有的台阶"：逐像素差查不出它（台阶两侧各自只差 5~7，都没到可见阈值 8），
   可两块交界处画布是一级台阶、原图是平滑过渡，肉眼看就是一道弧线/一条缝。
   判据是"画布这一步的台阶 ≥7 而原图这一步 ≤6"，命中的像素按目标色补掉（实测台阶从 10 级降到 3 级）。
   然后分三类补漏：**真空白**（画布这块还是白的、而原图不是）、
   **小块/细条错误**（按"总误差量"排序、迭代 3 轮，免得几十像素的深色漏笔永远排在几千个大块后面被丢掉）、
   **交界过渡带**（默认关，实测负收益，见下面的坑）。
   每一处都严格只覆盖"确实画错的那几个像素"，不外扩，免得把周围本来正确的地方也刷掉。

**自动模式**：先算"纹理强度"（原图与 median3 去噪图的差异占比）。纹理强的图（照片/扫描件，>6%）
自动切成另一套参数：色数 40~44、最小区块更小、铺色笔更细（`bwF` 0.12）、笔数上限放宽到 40000；
细线的对比门槛也放低（照片的"细线"多是毛发/发丝，该画），平涂类保持高门槛（纸纹脏痕不写上去）。
这就是照片类读数能从 38.7% 降到 25.0% 的主要原因。

**回放**：每笔都是一条走廊多边形 + 笔尖轨迹 + 一个纯色。时间轴把每一笔拆成"抬笔移动 + 换阶段停顿 + 落笔绘制"：
手就在旁边时顺势接着画（不占时间），隔得远才抬笔沿浅弧线飞过去（纸面留一条淡淡的虚线），
换阶段前会停一下像在回看；抬笔移动的总量封顶在总时长的 20%，所以整段过程稳定在 4 分钟。
落笔时按"已扫过 + 笔尖前沿"逐帧合成，笔尖前方带半透明湿边；进度条拖动靠关键帧位图，秒级响应。

## 细节上的几个坑（都在代码里处理了）

- 平涂和"透出原图"是两种完全不同的取舍：平涂必须在**边界**上想办法，所以取色时要避开区块边界的混色像素（否则会画出一圈亮边）；
- 细而弯的区块用"平行直线笔刷"必然漏涂，必须走骨架笔；
- **手抖必须"整块一起漂"**：若相邻两档笔各自随机方向偏移，中途就会互相错开漏出细缝（实测可见差异会翻倍）；
  所以手抖的相位/波长按色块取，横向范围还要按最大漂移量外扩一档。
- **勾线层要画在铺色之前**：线稿笔的画廊会外扩 2px，若放在铺色之后，这圈深色描边就压不回去（平均差 2.7 → 4.9）；
  现在勾线在铺色之后执行但**不扩边**（`dilInk: 0`），既有"先铺色再勾线"的过程感，又保住了还原度。
- 补笔只在**结构性错误**（线稿、边界过渡带）上做，大片渐变差异补了会变成块状拼贴；
- **"补漏"有两个反直觉之处**：一是它的裁剪掩膜**不能外扩**（把洞周围本来正确的像素也刷成洞的均值色，指标反而变差）；
  二是**不能按包围盒判大小**——沿色块交界的白线又长又细，包围盒很大但厚度只有 1~2px，
  按包围盒会被全部漏掉，得按厚度判；而且"真空白"要单独拎出来补，因为白点常常贴在大片差异上，会被"大块不补"的规则连带跳过。
- **"空白点"要一路查到网页端才算数**（这一块踩得最深，最后做成三层保险）：
  1. **光栅口径必须和网页端一致，而且要按"覆盖率"算**：网页端是"canvas 抗锯齿多边形 ∩ 1 位硬遮罩"，
     一个像素只被笔形斜斜擦过 20% 时，网页端看起来仍是半白的。管线原来的光栅是**二值**的——
     擦到一点就算"画上了"，于是补笔不再去管它，网页端就留一个白点（实测照片类 11 个 1px 点）。
     现在管线用 `fillPolyCov()`：**非零环绕 + 每像素 2 条亚扫描线 + x 向精确积分**算出覆盖率，
     盖不到 `coverMin`（0.7）就当没画上，后面的补笔/补漏自然会把它补实。
  2. **多边形的环绕规则也要一致**：canvas 的 `fill()` 用**非零环绕**，管线的扫描线填充原本用**偶奇**——
     笔形自相交的地方（收笔的尖、手抖拐角）偶奇会"挖洞"，网页端却是实心的。两边都改成非零环绕。
  3. **补漏的判据不能用"几何上没盖到"**：照片里没盖到的像素成千上万（一片纹理区就有几万），
     而补漏是按连通块**从大到小**取的——真正刺眼的 1~2px 白点排在最后，被数量/笔数门槛整批丢掉。
     改成**肉眼口径**："画布上这点是白的（三通道都 ≥ 244）且原图不该白"。两条门槛必须
     原图 ≤ 画布，否则"补上目标色之后仍然算白"，会反复补、补不掉。
  4. **补上了不等于盖到了**：沿骨架走的笔形在细缝/拐角/极扁的形状上可能盖不到像素中心（补了等于没补）。
     所以每个补漏块补完要**自检**：还是白的像素再用"方点笔形 + 严格掩膜"兜底（方框一定包含像素中心）。
  5. **零白点是"验"出来的，不是"算"出来的**：管线跑完，网页端会在一张**自己的离屏画布**上把成品
     整幅重画一遍，直接在真实渲染结果上扫白点，有就补（补笔只盖那几个像素，周围不受影响），迭代到扫出 0 个。
     这一步**在后台跑、不挡开播**——用户要的是"马上开始画"；补笔备好后追加到时间轴末尾，
     播放到收尾阶段时自然会画上（真画完了还在补，就直接补到成品上）。状态行常驻"白点自检 0 个"。
     三张示例图实测：插画 / 照片 / 海报 **全 0**。
     另外：分片推进**不能依赖 `await setTimeout` 链**——标签页被节流时那种链会长时间不回来，
     页面看着像卡死；现在由主循环 `tick()` 推进（rAF 和 50ms 看门狗双驱动，播放能跑，自检就一定能跑）。
- **1px 白缝的另一个根源是抗锯齿本身**：两个色块 hard 相接时，两边多边形边缘都是半透明，
  叠起来只剩 ~75% 不透明度，底色白就透出来一圈。解决办法是每一笔填色后再**沿笔形描一圈同色细边**
  （`lineWidth 1.4`，圆角圆接），把边缘的"半透明"变成实心——白缝从根上不再产生（这一改比补笔更管用）。
- **省笔的核心手法：把散点补丁合并成"一笔"**（照片类的补笔从 2 万笔降到几千笔，画面一个像素没变）：
  补笔大多是 5~16px 的小点，一拍一笔。但每一笔的笔形最终都会被它自己的 **1 位裁剪掩膜**裁掉多余部分——
  也就是"笔形只要盖住自己的掩膜"就够。于是把同一格、同一色阶的补丁并成一笔：
  掩膜取并集、笔形取并集**外框**（外扩 0.5px 保证盖住每个像素中心）、颜色取桶内加权均值。
  因为各补丁的掩膜互不相交（谁也没盖住谁），合并只带来"每通道 ≤ 半个桶宽"的取色偏差，笔数却少一个数量级。
  实测桶宽（`patchShift`）3 = 每桶 8 个色阶时，照片 -42% 笔、指标反而略好；桶宽 4 就明显掉质量了。
  外框要设上限（`patchBox:128`）：外框越大，网页端每一笔要清/合的画布越大、掩膜占的内存也越多
  （实测无上限时掩膜总面积从 4.8Mpx 涨到 90Mpx+）。
- **同一个区块来回的几档要接成"一条连续走笔"**（`joinPass`/`joinCd`）：一档一笔时，铺色阶段会有
  几千笔"一排平行线"，人不是那么画的。做法是把各档的走廊多边形并成一个**非零环绕**多边形（"链式钥匙孔桥接"：
  每个环的入口取离上一个环入口最近的顶点，进出各走一遍 ⇒ 桥接边正反相抵、不产生面积，填充结果就是各环的并集）。
  两个坑：① **各环方向必须先统一**——方向相反的两环在重叠处环绕数相加变成 0 会挖洞，而相邻两档本来就重叠 38%；
  ② **桥接只能连相邻的环**，连到远处的锚点会在区块中间拉出一条 1.4px 的描边线（同色看不见，但在渐变区块上成一道痕）。
  颜色口径：整条连笔取"第一档的色"，所以档间色差超过 `joinCd` 就另起一笔——实测 18（约 6 级/通道）是质量拐点，
  24 以上开始把区块内的颜色变化抹平（海报可见差异 21.6% → 22.5%）；18 时三张示例的成品指标都比不连笔**更好**
  （连笔顺带少了重叠笔的"花"）。铺色阶段笔数：插画 726→329、照片 5268→3091、海报 3890→2133。
- **"省笔"别顺手改掉补笔预算的口径**：轮次预算是按"补丁个数"算的（`nPieces`，起算点 = 补笔前已有的笔数）。
  如果按"笔数"算，合并本身会让补笔多跑一轮——质量变好、耗时也变长，那是另一件事，不该被省笔带出来。
- **"沿交界补一条中间色过渡带"实测是负收益**（`edgeFill`，默认关）：我们的二值裁形边界像素在目标图里
  大多本来就是纯色（抗锯齿过渡只有亚像素宽），把中间色补上去反而把它们刷偏——平均差 2.14 → 2.27、笔数 +35%，
  而"可见差异"只动 0.06%。要做对得上亚像素级的掩膜渲染（覆盖率加权），那是另一个量级的改动。
- **自测口径要和网页对齐**：管线自带的差异读数用的是"羽化光栅"，网页端是硬边裁剪 + canvas 抗锯齿，
  1px 尺度上不一样（照片类空白数能差 3 倍）。给管线加个 `hardRaster` 开关（网页端是硬边裁剪时口径一致），
  再配合 `dev/blanks.mjs`（统计"该有色却是白"的像素）才能测准"白点"这类问题。
- **录制视频不能靠"每帧增量"推进**：标签页被节流时 rAF 不触发、`setInterval` 掉到 1Hz，
  按播放速度走的录音会变成 1× 慢放（4 分钟）。改成"按真实时间算该画到哪一帧"就稳定了；
  另外机器太慢时要允许提前结束，但**必须把剩下的笔补完**，否则成品不完整。
- 照片纹理会让区块数爆炸（几千块 / 上万笔），所以有总笔数上限与收益收口。

## 还能往哪儿优化（按性价比排）

1. ~~细笔补漏还能再省~~ / ~~照片的笔数偏多~~：已解决——补笔按"同格同色阶"合并成一笔（照片 29820 → 17365，
   插画 8947 → 5079），收尾补漏也走同一套机制（-2100 笔）。
   ~~一个区块内一档一笔~~：已解决——同区块来回的几档接成一条连续走笔（见上面的坑，铺色笔数近半）。
   **还剩的大头是"补丁笔"**（残差/补漏的小补丁，占海报总笔数 6 成以上）。`dev/stroke_breakdown.mjs` 的读数：
   海报 14082 个补丁 → 9315 笔（平均只合了 1.5 个/笔），原因是补丁颜色散在 2600 多个"色阶桶"里。
   想再压只能动三个旋钮，都有代价（实测，海报）：
   - `patchBox` 128→192：笔数 −7%，成品指标不变（像素级等价），但**掩膜内存 12.5 → 21.4MB**（照片类会到 58MB）；
   - `patchShift` 3→4（每桶 8 → 16 色阶）：笔数 −28%，色阶桶 2658 → 681，但可见差异 +0.2~0.9 个百分点；
   - 把补丁笔的笔形从"一个大外框 + 掩膜"换成"逐补丁小矩形的并集"（并成一条非零环绕多边形）：
     掩膜内存能直接省掉，笔数也能再合——但要改笔形/渲染/导出的口径，属于另一轮改动。
2. **提炼耗时**：照片类现在 12~17 秒（比省笔前还快一点）。还能再快的是"覆盖率光栅"这步——只在笔形边缘附近算覆盖率。
3. ~~残留下的 1~7px 小白点~~：已解决（管线按肉眼口径补 + 网页端成品自检，三张示例图均 0）。
   想更快的话还可以把"自检"这步的整幅重画省掉（只在成品上按几何重算覆盖）。
4. **笔触质感还能再细分**：现在三档风格只是"笔宽 + 笔形 + 重叠"的差别，还可以给铅笔加斜向排线、给油画加水痕/厚涂边缘。
5. **起稿还能更"人"**：目前是"沿最终轮廓随手简化"，再往前一步是"先画一版粗略的、铺色时发现不对再改"（要引入局部重画逻辑）。
6. **导出再加 GIF**：现在是 WebM（体积小、清晰），GIF 需要自己写调色板量化 + LZW，工作量大但社交平台更通用。
7. **大图支持**：现在长边压到 1024，可以做成可选 2048（笔数会翻几倍，需要配更激进的收口策略）。

## 目录

```
index.html            页面（上传 + 参数 + 画布 + 回放控件 + 四步进度条 + 导出按钮）
js/app.js             主线程：图片预处理、界面、回放引擎（含抬笔移动/阶段停顿）、导出、差异读数
js/worker.js          Worker 入口
js/pipeline.js        全部算法（纯 JS，无依赖；也能在 Node 里跑）
samples/              示例图（含授权说明见 samples/CREDITS.md）
dev/                  开发用小工具
  run_test.mjs        Node 里直接跑管线并出还原度数据（量化回归用，PIPE= 可指定其它管线文件做 A/B）
  timeline_check.mjs  离线核算"抬笔移动/停顿/绘制"三段时间，检查总时长是否锁在目标值
  err_map.mjs         错误分布诊断：按格子列出"目标色 → 画面色"，定位偏色/漏画的区域
  blanks.mjs          空白统计：找出"该有色却是白"的像素，按大小排序（验收"白点"问题用）
  rgb_diff.mjs        两张结果图的差异定位（改造前后对照）
  rgb2png.py          结果 .rgb → PNG，直接看图
  mkraw.py            把图片转成 Node 测试用的 .raw
  make_sample_illustration.py  生成 sample-1（自绘 CC0 插画）
  probe_point.mjs / diag_strokes.mjs  排查"某个像素/某条线为什么不对"
  aa_blanks.mjs       按**网页端真实渲染**（canvas 抗锯齿贝塞尔/多边形 ∩ 1 位遮罩 + 同色描边外扩 0.7px + 逐笔 source-over）
                      复算成品，统计空白点/亮斑并给出归因（"没笔盖到 / 半透明缝 / 被亮色笔盖错"）——白点问题的验收入口
  stroke_stats.mjs    笔画来源分解：按阶段/形状/站点统计笔数，找出"笔数大户"
  stroke_breakdown.mjs 笔数分解表：起稿/铺色/勾线/残差每一轮/补漏各贡献多少笔、区块面积分布、
                       铺色笔按区块面积分解、补丁笔合并效率、裁剪掩膜内存（省笔改造的决策依据）
  patch_map.mjs       补丁热力图 + 残差错误图（底图压暗、补丁标黄/红、差异分三档上色）——
                       "补丁到底是纹理还是没画好的边角"一眼可判；DUMP= 可导出成品画布
  crop_cmp.py         局部放大对照：原图 | 成品 并排（最近邻放大 N 倍，看像素级差别）
  sweep_patch.mjs     省笔参数扫描（patchShift/patchCell/patchBox/coverMin），同时看笔数、差异、掩膜内存
  where_dots.mjs      按"阶段 × 是否有区块 × 笔尖 × 路径点数"交叉统计（含各产出站点的计数）
  probe_dot.mjs / probe_cov.mjs  单像素追查：列出所有掩膜含它的笔、逐笔算真实覆盖率
```

> 改了 `js/` 里的脚本后，记得把 `index.html` 里 `<script src="js/app.js?v=N">` 的 `N` 递增一下：
> GitHub Pages 对静态资源有 10 分钟缓存，容易让人以为改动没生效。

本地跑回归：

```bash
python dev/mkraw.py samples/sample-1.jpg dev/s1.raw
node dev/run_test.mjs dev/s1.raw 24 out.rgb      # 还原度数据
node dev/timeline_check.mjs dev/s1.raw 24        # 回放时长核算
```

## 兼容性

需要支持 `Worker` / `Canvas 2D` / `createImageData` 的现代浏览器（Chrome / Edge / Safari / Firefox 近几年版本都可以）。
1024px 的图在普通笔记本上提炼约 8~20 秒，回放本身很轻（每帧只合成当前一笔）。
